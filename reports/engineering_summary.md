# ATE AI Engineering Assessment — Engineering Summary

## Project Overview

This project demonstrates an end-to-end AI/ML pipeline for Automated Test Equipment (ATE) semiconductor data. It covers synthetic data generation, cleaning, yield analytics, failure prediction, anomaly detection, and explainability — all exposed through an interactive Streamlit dashboard.

## Data Generation Approach

- **Rows**: ~8,000 synthetic ATE test records generated by `generate_test_data.py`.
- **Devices**: 1,600 unique Device IDs, each tested across 5 standard tests (P301–P305).
- **Tests**: SCAN_CHAIN, LEAKAGE_TEST, TIMING_TEST, VOLTAGE_REG, POWER_TEST.
- **Class split**: ~85% PASS / ~15% FAIL (injected stochastically).
- **Injected quality issues**: ~5% missing values in Measured_Value, Temperature_C, VDD_V; ~2% exact duplicate rows; ~3% outlier measurements.
- **Seed**: numpy seed 42 for full reproducibility.

## Yield Analysis Highlights

- Overall yield is approximately 85% (matching the synthetic generation ratio).
- Yield is roughly uniform across Test IDs and Lot IDs by design.
- Top failure modes: TIMING_VIOLATION, LEAKAGE_EXCESS, VOLTAGE_DRIFT, POWER_OVERSHOOT — distributed uniformly among FAIL records.
- The heatmap (Lot × Test) shows no strong lot-specific failure patterns (expected with synthetic data).

## ML Model Comparison

Three models were trained with a leakage-safe feature set (excludes Measured_Value, Failure_Mode, Yield_Impact):

| Model               | F1 (FAIL class) | ROC-AUC | PR-AUC |
|----------------------|------------------|---------|--------|
| Baseline (majority)  | 0.0000           | 0.500   | 0.156  |
| Logistic Regression   | 0.2149           | 0.465   | 0.151  |
| Random Forest         | 0.0000           | 0.496   | 0.150  |

**Selected model**: Logistic Regression (best F1 for the FAIL class).

Low F1 is expected because the leakage-safe features (VDD_V, Temperature_C, Retest_Count, Test_ID, Test_Name, Lot_ID, Wafer_ID) have limited predictive power over randomly assigned PASS/FAIL labels in synthetic data.

## Anomaly Detection Approach

- **Algorithm**: IsolationForest with RobustScaler preprocessing.
- **Features**: normalized_distance (Measured_Value vs spec midpoint/width), Temperature_C, VDD_V, Retest_Count.
- **Configuration**: 300 estimators, contamination="auto", seed 42.
- **Output**: anomaly_score (higher = more anomalous) and is_anomaly flag per record.
- Anomaly detection uses Measured_Value (post-test), making it suitable for retrospective analysis rather than pre-test prediction.

## Key Findings and Recommendations

1. The pipeline correctly handles the full lifecycle: data generation → cleaning → analytics → ML → anomaly detection → explainability → UI.
2. With real fab data, the ML model would benefit from temporal features, lot-level aggregates, and process parameters not present in this synthetic dataset.
3. The anomaly detector successfully flags injected outlier measurements.
4. Citation-backed explanations give users traceability from prediction to evidence.

## Assumptions

- Data is synthetic and generated with a fixed seed for reproducibility.
- The ~85/15 PASS/FAIL split is enforced stochastically; actual class distribution may vary slightly.
- Failure modes are assigned randomly (no causal relationship with measured values).
- The leakage-safe feature set intentionally excludes post-test variables.

## Limitations

- Synthetic data does not reflect real semiconductor fabrication patterns.
- No temporal or sequential features (wafer processing order, time-series).
- SHAP explainability is not included in the default flow (available as a library dependency).
- Model performance on synthetic data should not be extrapolated to production scenarios.
- The Streamlit app is designed for demonstration and local evaluation, not production deployment.
